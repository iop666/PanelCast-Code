---

## 1. 这个实验要回答什么

只有一个问题：**AI 能不能看懂这本漫画，并写出"不是逐格复述"的连贯解说稿。**

拆成两个可分别观测的子问题：

- **E1 理解力**：从整页画面中，能否正确判断"谁在做什么、为什么、接下来会怎样"。
- **E2 写作力**：能否把画面转成有节奏、有因果、有取舍的旁白，而不是"然后他…然后她…"。

如果 E1 或 E2 任一为否，工作台做得再好也没有意义。**这是项目的生死线，不是优化项。**

### 非目标（本实验一律不做）

- 不做自动分格、不做切图、不做 OCR 管线
- 不做 TTS、不做字幕对齐、不做视频渲染（M0 只产出**文字稿**）
- 不跑全本 169 页
- 不写任何 `panelcast` 包代码

## 2. 素材与页面定位

### 2.1 已实测的页面结构（本次核对，勿再自行推断）

| 页 | 内容 | 版式 |
| --- | --- | --- |
| `page_0001` | 封面 | 单页全幅 |
| `page_0002` | 空白/版权类 | 近乎空白（19 KB） |
| `page_0003`–`page_0004` | **序章**（死亡场景、女神登场） | 5 格，带边框，阅读顺序清晰 |
| `page_0005` | **第一章扉页**（标题页） | 全幅跨页插画，无边框，无剧情 |
| `page_0006` | 城镇全景 + 街景 | 上方整幅无边框大格 + 下方 3 个带框格 |
| `page_0007`–`page_0012` | 第一章正文展开 | 混合版式 |

**M0 取样：`page_0005` ~ `page_0012`，共 8 页。**
剧情实质从 `page_0006` 开始，`page_0005` 仅作章节标记——**在稿子里必须体现"这是章节开场"而不是当成剧情格**，这本身就是 E1 的一个观察点。

### 2.2 三个必须记录的技术障碍（会直接拉低得分，需单独归因）

1. **竖排繁体中文，从右到左**。对视觉模型的文字识别是明显难点，很多模型会读错或漏读对白。
   → 记录表必须单独统计"对白读取错误"，不能混进"剧情错误"里。
2. **页内印有原书页码**。`page_0008` 右下角印着「6」，说明我们的 `page_XXXX` 与原书页码相差 2。
   → 任何"第几页"的表述都要注明用的是哪套编号，否则人机沟通会错位。
3. **版式非规则网格**。存在无边框大格、贴页边裁切的格、人物越过分栏线、对话框跨格。
   → 这正是"自动分格不可靠"的实证，也是本实验只用整页图、不切格的理由。

### 2.3 小说侧对应段落

- 小说 `chapter01.xhtml`（19666 字）标题与漫画第一章扉页**完全对应**，章节级对齐成立。
- 需要人工截取其中「转生落地 → 进入城镇 → 感叹异世界」这一段，约 **1200–2000 字**。
- 截取边界要求：起点从主角与女神落地后的第一个场景描写开始，终点到主角进入城镇、初步安顿为止。
  **不要**截到后面的战斗或人物介绍段落。
- 截出的文本存为 `m0/novel_excerpt.txt`，并在记录表里写明首尾各 20 字，便于复核。

> 注：`page_0003`–`0004` 对应小说「序章」，可作为**章节对齐的旁证**顺手验证一次（比对一下序章内容是否确实只覆盖这 2 页）。不算 M0 主任务，5 分钟内可完成。

## 3. 三版稿的构造（同一段内容，三种信息条件）

三版必须**覆盖同一段剧情**、**长度相当**，否则无法比较。

### 通用输出规格

- 中文解说稿，**60–90 秒**，按中文 TTS 约 4.3–4.8 字/秒折算 → **260–400 字**
- 分 **3–5 段**，每段对应 1–3 个画面
- 必须是"讲故事"，不是"报画面"
- 人物一律用**原名**（佐藤和真 / 阿库娅）；若无法确定姓名，必须用「戴帽子的女孩」这类**占位描述**，
  **严禁编造名字**

### V1：只看漫画

输入：`page_0005`–`page_0012` 共 8 张整页图，无任何文字辅助。

### V2：只看小说

输入：`novel_excerpt.txt`（2.3 截出的段落），**不给任何图片**。

### V3：小说事实 + 漫画画面映射

输入：8 张整页图 + `novel_excerpt.txt`，并附以下约束：

```
以漫画画面作为镜头依据（旁白描述的内容必须在画面中真实存在），
以小说文本作为事实依据（人物关系、因果、背景）。

规则：
1. 小说中有、但漫画画面没有表现的情节，不得作为画面描述写进来。
2. 画面中有、但小说未提及的细节，可以描述，但不得据此编造剧情。
3. 两者冲突时，以漫画画面为准描述"看到什么"，以小说为准描述"意味着什么"。
```

### 每版必须输出结构化结果（便于评分与后续复用）

```json
{
  "version": "V1|V2|V3",
  "model": "<模型标识>",
  "segments": [
    {
      "page": "page_0006",
      "narration": "……",
      "evidence": "画面中他站在城门口抬头看，分镜从上往下拉",
      "confidence": "high|medium|low"
    }
  ],
  "char_count": 0,
  "self_reported_uncertainty": "模型自己说明哪里没把握"
}
```

`evidence` 字段是硬要求：**每段旁白都要能指回具体画面**。写不出 evidence 的段落，
本身就是"胡编"的强信号。

## 4. 评分（人工，不由模型自评）

每版按 5 维打 1–5 分：

| 维度 | 5 分标准 | 1 分标准 |
| --- | --- | --- |
| **事实准确** | 与漫画/小说无冲突 | 出现关键剧情错误 |
| **人物指认** | 姓名、关系全对 | 张冠李戴或凭空编名 |
| **连贯性** | 有因果、有节奏、有取舍 | 逐格流水账 |
| **画面匹配** | 旁白描述的东西画面里确实有 | 描述了不存在的画面 |
| **可听性** | 像视频旁白，能听下去 | 生硬、书面、念不下去 |

### 另外必须统计两个硬指标

- **逐格复述率**：统计有多少段是"某格画面 → 一句话直译"。> 50% 即判失败。
- **对白读取错误数**：因竖排繁体识别错误导致的剧情偏差，单独计数（归因用）。

### 否决阈值（事先定好，不许事后放宽）

任一条命中即判该版失败：

1. 出现 **≥2 处凭空捏造**的人物名或事件
2. 逐格复述率 **> 50%**
3. 事实准确维度 **≤ 2 分**
4. **V3 相对 V1 没有可感知提升**（小说补充无价值 → 架构假设要改）

> 阈值必须在看到结果之前写死。看到结果再定标准，等于没标准。

## 6. 执行方式：一次长任务跑完，中途不回报

本实验**一次性派单**，执行方从 S0 连跑到 S4，中途不设人工确认点。
每个 stage 结束自检，自检不过自己修，**不要停下来问**。
只有两种情况允许中断：S0 判定无视觉能力（走降级路径）、或遇到无法自行解决的阻塞。

### S0 视觉能力自检（30 秒，决定后续路径）

取 `page_0006`，问一个**只有看图才能答**的问题（例：这一页最上方那一大格画的是什么场景）。
答不出、或答案明显是猜的 → 判定无视觉能力，报告首行写 `vision: no`，跳过 S2，
只交付 S1 + S3 的产物。

### S1 素材与文本准备（不需要视觉）

1. 从 `chapter01.xhtml` 截取 `m0/novel_excerpt.txt`（按 2.3 边界），记录首尾各 20 字
2. 复制 `page_0005`–`page_0012` 到 `m0/pages/`（**只复制，不缩放、不切格、不处理**）
3. 建 `m0/results.csv` 空表（表头照抄第 5 节）
4. 写 `m0/prompts/V1.txt`、`V2.txt`、`V3.txt`（V3 必须含第 3 节约束原文）
5. 做 2.3 末尾的序章对齐旁证，写进 `m0/alignment_note.md`

全部是文件操作。允许新增 `m0/`，不许动 `panelcast/`、`tests/`。

### S2 生成三版稿（需视觉能力）

- 每版至少 **2 个不同厂商的模型**各跑一次，否则分不清"模型不行"还是"任务不行"
- 落盘 `m0/drafts/{V1,V2,V3}-{model}.json`，schema 见第 3 节
- V2 是纯文本任务，无视觉也能跑——即使 S0 判定无视觉，**V2 仍必须交付**

### S3 自检（不合格就地重写，最多重试 2 次）

每份稿逐条核对，不合格**不许当成功交付**：

- JSON 字段齐全，`segments` 非空
- `char_count` 与 `segments` 正文实际字数一致（允许 ±5 字误差）
- 总字数 260–400，段数 3–5
- 每段都有非空 `evidence`
- 无编造人名（出现小说/漫画里没有的名字 → 直接判该稿不合格）

### S4 一次性交付

一份清单 + 一句话结论，不要贴正文：

```
vision: yes|no
files: <逐个列出>
drafts: <每版每模型 字数/段数>
excerpt: <首 20 字> ... <尾 20 字>
alignment: <序章是否对齐，一句话>
blocked: <无 / 具体卡点>
```

### S5 评分——人工做，模型不得参与

模型自评没有意义。评分由人看稿 + 翻原页完成，填 `results.csv`。

## 7. 判定之后的分支

| M0 结果 | 结论 | 下一步 |
| --- | --- | --- |
| V1 或 V3 达标 | 内容成立 | 进 M1 最小闭环（分格 + 人工修正 + TTS + 渲染） |
| 只有 V3 达标 | 小说是必需品 | 架构改为"小说为骨架、漫画为画面"，M1 必须先做对齐 |
| 三版全不达标 | **产品假设不成立** | 停掉工作台开发，重新想产品形态（如只做"人工写稿 + AI 配画面"） |
| 理解对但写作差 | 是 prompt/风格问题 | 加一轮风格实验（3 种解说风格），不推翻架构 |

**第 3 行是这个实验存在的全部意义。** 如果三版都写不出能看的东西，越早停损失越小。
