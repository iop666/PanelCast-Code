## 0. 产品边界（先定清楚，否则后面全错）

PanelCast 不是"把竖版改造成切格视频"，而是**同一套内容底座 + 两套视觉生产层**。

### 0.1 竖版模式：保持现状，不要求切格

- 一张完整漫画页作为主要画面，等比适配、白底/模糊填充、章节标签、底部字幕、配音、页面切换 —— **全部作为基线冻结**。
- 不以单个漫画格为展示单位，**不把逐格切图列为竖版必经门禁**。
- `panels.json` / 分格编辑器作为辅助能力保留，但不得为满足横版需求破坏竖版整页工作流。
- 竖版出片明确选择 `visual_mode=page`，页面引用直接指向原始页图。

### 0.2 横版模式：独立扩展方向，需要格级素材

- 白色背景为主，按讲解节奏展示一张或多张独立漫画切图。
- **必须**有本地网页人工切格工具：逐页打开、缩放平移、画框、调整、确认阅读顺序。
- **切图允许重叠**：每次切图都从原始页面独立裁切，B 框可以覆盖 A 框的一部分，重叠区域在两张切图里都保留。
- 切图边界由人确认；阅读顺序由机器提建议、人确认或修正。**不得把"画框的先后顺序"当阅读顺序。**
- 自动排序必须支持低置信度提示、人工拖动、锁定、重算，**不得静默把不确定的顺序当正确结果**。

### 0.3 共用与分开

| 共用（内容底座） | 分开（视觉生产层） |
| --- | --- |
| 来源素材、章节索引 | 整页图引用 vs 切图资产 |
| 小说纯文本、剧情 Beat | 竖屏页面布局 vs 横版多图布局 |
| 来源对齐（S5a）、讲稿、配音、句锚点 | 页面时间窗口 vs 格级视觉时间轴 |
| 内容审计、交付管理 | 竖版渲染器 vs 横版渲染器 |
| 缓存、增量重跑 | 竖版视觉验收 vs 横版视觉验收 |

**两条禁止**：不得为横版切格强迫竖版改用格级数据；不得把竖版页面时间轴逻辑未经验证直接套到横版。

## 2. P0：内容可信度与规范闭环

> 逐项任务书（含文件白名单、验收命令、工作量预估）见
> [`docs/tasks/P0-execution-plan.md`](tasks/P0-execution-plan.md)。

### 2.1 为什么 P0 必须排第一

当前十章成片**技术验收 15/15 全绿**，但这只证明"视频生成成功"，不证明"剧情讲解正确"。
两件事不能混为一谈：

- 十章讲稿产出于 S5a（底稿对齐）写进规范之前，**没有任何一段旁白能追溯到小说段落**。
- 已经出现过事实错误：第六章把"铁笼泡湖净化"写成"哥布林绑票 + 竹筏 + 大青蛙吞笼"，
  画面里没有、小说里也没有。
- 第一～五章是同一套"只看画面"方法写的，**风险同级，尚未逐章复核**。

所以 P0 的目标不是"补十份 JSON"，而是**把这十章从技术验证片升级为内容合格片**。

### 2.2 任务清单

- [ ] **P0-01 核实对应关系**
  核实十章旧成片、讲稿、小说源文件、章节映射的真实对应关系。
  产物：一张对照表（章 → 小说段区间 → 讲稿段数 → 成片 hash），写进 `m1/audit/chapter-map.md`。
  **不得凭记忆填，必须逐章读小说原文核对。**

- [ ] **P0-02 建立底稿 `novel_ref.json`**
  十章各一份，覆盖本章所有漫画页；每个 Beat 标 `drawn / omitted / altered / original`。
  产物：`m1/v{n}/chNN/work/novel_ref.json` × 10。
  门禁：`beats` 覆盖全部页；四类计数自洽；`original` 必带 `pages`。

- [ ] **P0-03 讲稿来源复核（100%，不是抽查）**
  逐段检查：这句话描述的动作/人物，在这页上看得见吗？看不见的话小说里有吗？
  三种结论都要记：看得见 / 小说有但没画 / 两边都没有。
  产物：`m1/audit/script-audit.md`，逐段列表 + 结论 + 需改写的段落。
  **两边都没有的段落必须改稿，不许为保留历史成片迁就原稿。**

- [ ] **P0-04 重出受影响的成片**
  改稿后重跑 S6–S9，只重算受影响段落（TTS 内容寻址缓存会自动命中未改的段）。
  产物：十章 mp4 + `run_report.json`，且 `delivery.md` 标明"内容已审计"。

- [ ] **P0-05 `m1 novel --align / --check` 代码化**
  `--align` 只生成候选与骨架，**不得把候选自动标成人工确认**；
  `--check` 校验：`novel_ref.json` 存在 → `novel_ref.source.text_sha256` 与当前
  `novel_index.json` 的 `file_sha256` 一致 → 每段有有效 beat → beat 的页映射合法。
  五步任一不过就退出码 3。
  > 注意哈希口径：比的是 `text_sha256`（`novel.txt` 落盘字节），**不是** `source.sha256`
  > （EPUB 原文件）。两者永远不相等，混用会让底稿永远判定失效。见规范 §4.3.9。

- [ ] **P0-06 正式出片门禁**
  `m1 run` 正式路径检查：底稿 hash、beat 引用、**内容审核报告（`script-audit.json`）
  有效性**——报告里的 `script_sha256` / `novel_ref_sha256` / 逐段 `text_sha256`
  必须与当前文件一致，且每段有 `reviewed_by` 是人的状态记录。
  临时预览走显式 `--draft`，**draft 产物不得冒充正式交付**（文件名或报告里要有标记）。

- [ ] **P0-10 `m1 verify --visual` 视觉验收落地**
  路线图此前没有这条任务，但 CLI 里已经有 `--visual` 开关，属于**文档漏登记**。
  **不做成"抽六帧看看"**，按规范 §9.5 分三层：

  | 层次 | 查什么 | 判据 |
  | --- | --- | --- |
  | L1 渲染完整性 | 空白/黑屏/缺失图片/冻结帧 | 硬失败 |
  | L2 视觉布局 | 漫画裁切/字幕遮挡/画面越界/比例异常 | 硬失败 |
  | L3 时间同步 | **每个切页点前后各抽一帧** + 最长停留页首尾 + 字幕段比对 | 硬失败 + 疑似清单 |

  L3 的切页检查**不能抽样**：249 次切页就是 249 个必查点，
  随机抽帧会恰好漏掉切换瞬间的闪黑/滞后/叠页。
  **边界**：`--visual` 的 PASS 只表示"渲染正常"，**不得**作为内容审核的置位依据；
  但 FAIL 可以直接阻断出片。剧情正确性永远归 §9.4 人工 + `script-audit.json`。
  对应规范：§9.3 抽帧复验、§9.5 视觉验收。

  其中第 5 步硬性要求：**迁移不得自动推断剧情来源**——`source_refs` 只能来自
  `novel_ref.json` 的既有 beat 或人工标注，禁止"看画面猜一个 beat 填进去"。

  **三态约束（规范 §4.3.4）**：迁移跑完只能落到 `migrated_unreviewed`，
  不许因为"JSON 转换无报错"就进 `content_reviewed`。
  `content_reviewed` 只能由审核流程置位，`approved` 还要再过出片门禁。

  前置：P0-02（十章 `novel_ref.json` 齐备）。

### 2.3 P0-RELEASE-GATE 正式内容生产资格

> **这不是第十二个开发任务**，是 P0 做完时的总验收条件。
> 九条必须同时满足，缺一条就是"不具备量产资格"。完整判据见规范 §9.6。

| # | 条件 | 怎么验 |
| --- | --- | --- |
| 1 | 原有十章完成 100% 内容审计 | 十章 `script-audit.json` 全 `approved` 且逐段覆盖 |
| 2 | 新版 Schema 与旧版迁移通过 | 十章 v2 + schema 校验；`.bak` 可回滚 |
| 3 | 小说来源哈希门禁通过 | 十章 `--check` 全过（含 `text_sha256`） |
| 4 | 审核报告与当前讲稿版本一致 | 三层哈希全对得上 |
| 5 | 正式出片门禁无法绕过审核 | 有测试证明 |
| 6 | 竖版完整页面路径正常 | 十章 `visual_mode=page` 全链路出片 |
| 7 | 横版未被错误设为竖版依赖 | 竖版不读 `panels.json` / `profile.json` |
| 8 | 视觉验收能发现预设故障样例 | 注入 5 类故障，`--visual` 全报出 |
| 9 | 全部测试通过，失败与跳过如实记录 | 报告写 `Ran N / OK (skipped=M)` + 跳过原因 |

**第 8 条最容易走过场**：不能只跑真片说"没报错"，必须先注入已知故障确认能抓到。

### 2.4 P0 完成标准

1. 十章都有 `novel_ref.json`，且 `--check` 全过；
2. 十章讲稿 100% 段落有来源结论，无来源段落已改写；
3. 重出的十章成片，`delivery.md` 明确区分"技术合格"与"内容合格"；
4. 正式出片路径无法绕过来源门禁（有测试证明），**且无法绕过 `script-audit.json` 审核门禁**；
5. 主规范 / PROJECT-MAP / README / CLI 帮助文本四者一致；
6. 章节身份有全书唯一 ID，人工不再依赖模糊的 `id/number`，
   **且 `novel_ref` / `script` / 交付清单三处用同一个 `chapter_uid`**；
7. 十章脚本迁到 v2 schema，`source_refs` 无一条是自动推断出来的；
8. **§2.3 的 P0-RELEASE-GATE 九条全过。**

## 7. P5：平台合规与发布风险管理

> 定位：**降低违规、侵权和误判风险，并具备证据、申诉和快速修订能力。**
> **不是**研究绕过平台审核、版权指纹或内容检测的技术。

- [ ] **P5-01** `rights_manifest.json`：每集素材来源与授权状态
- [ ] **P5-02** 漫画/小说/音乐/字体/图片/音效/配音分别记录许可（不能只核漫画版权）
- [ ] **P5-03** 按平台、规则版本、查询日期维护发布前检查表
- [ ] **P5-04** 发布资产包 + 来源证据包
- [ ] **P5-05** 投诉/下架事件记录、素材反向定位、审核材料导出
- [ ] **P5-06** 争议素材替换、删改、重渲染、申诉材料准备流程
- [ ] **P5-07** 目标校验：策略是合规与可申诉，不是规避检测

**明确不做**：镜像翻转、裁切边缘、变速、变调、遮挡水印、拆分片段等规避手段。

## 8. 执行与汇报要求

每个任务必须：

1. 先核对真实仓库状态、分支、未提交改动，**不重复探测已知事实**；
2. 明确目标、文件白名单、明确不做的事、前置依赖；
3. **先写可复验的验收标准，再实现**；
4. 不改变竖版现有整页效果，除非任务明确要求且有基线对比；
5. 横版与竖版分开开关、分开配置、分开验收；
6. 不把"JSON 字段齐全 / 模型自评置信度高 / 退出码 0"当成内容事实已核实；
7. 不把待建写成已实现，不把未跑测试写成通过；
8. 清理素材/缓存/成片前先核查引用关系与可重建性；
9. 每轮交付完整报告（见模板）；
10. 门禁失败就标 `BLOCKED` 并停止依赖它的后续阶段，**不得绕过门禁出正式片**。

### 标准交付模板

```markdown
# TASK-ID 任务名称

## 目标
## 当前事实（已核实）
## 范围 / 文件白名单
## 明确不做
## 输入与依赖
## 实施方案
## 验收标准（逐条可复验）

## 执行结果
- commands:
- tests: total / passed / failed / skipped
- artifacts:
- hashes:
- manual_review:
- blocked:

## 未解决问题
## 下一任务建议
```

## 9. 决策记录

1. 竖版现有整页形态保留，不要求切格。
2. 横版必须独立建人工切格工具，**允许重叠裁切**，重叠像素分别保留。
3. 切图顺序机器建议、人工确认锁定，机器不得覆盖人工锁定。
4. 两模式共用内容底座，视觉资产与视觉时间轴分离。
5. 十章先做底稿追溯与内容审计，**仅补元数据不算正式稿**。
6. 介绍页按实际需求渐进生成，291 份占位不算资料库。
7. Skills 在真实命令与 schema 稳定后封装，不先堆空 Skill。
8. 资料搜寻属于后续阶段，必须带来源等级、版本、hash、权利状态。
9. "防下架"按合规、授权、证据留存、投诉应对建设，不做规避检测。
10. 竖版 S4 分格不是硬门禁（`--skip-panel-gate` 已存在），横版切格才是。
